RustyDrive-Streamer 架构设计与实现思路记录

2026-02-20 · #Rust, #OneDrive, #Emby, #Microsoft Graph, #中间件, #异步编程, #SQLite, #系统架构

RustyDrive-Streamer：基于 Rust 的 OneDrive + Emby 中间件设计记录

项目代号：RustyDrive-Streamer
目标：构建一个高性能、可增量同步、支持 Emby 播放直链的 OneDrive 中间件服务。

一、项目背景

在使用 Emby 对接 OneDrive 资源时，存在几个核心问题：

  1. Emby 不直接支持 OneDrive 元数据管理
  2. 直链存在有效期限制
  3. API 存在限流
  4. 文件增量同步效率问题

参考项目：

  • 🔗 GitHub 项目：bpking1/embyExternalUrl
  • 🔗 技术文章：从Emby直链初识NJS模块

最终决定使用 Rust 构建高并发中间件，彻底解决同步效率与播放稳定性问题。

一、系统总体架构设计

架构分层

输入端

  • 对接 Microsoft Graph API
  • 拉取文件元数据（id / name / cTag / folder）

存储端

  • SQLite 维护文件映射关系
  • 支持增量扫描
  • 支持断点续传

输出端

  1. 本地 .strm 文件系统结构
  2. HTTP 播放服务（302 重定向至直链）

二、技术栈选型（Rust Crates）

功能 技术
异步运行时 tokio
Web 框架 axum
HTTP 客户端 reqwest
数据库 sqlx (sqlite)
JSON 解析 serde / serde_json
并发控制 tokio::sync
递归支持 async-recursion

核心设计目标：

  • 全异步
  • 高并发
  • 非阻塞 IO
  • 数据一致性优先

三、数据库设计（SQLite）

数据库是系统核心，支持：

  • 增量更新
  • 删除检测
  • Token 持久化

表一：settings

用于保存 OAuth2 信息

字段 类型 说明
key TEXT PK refresh_token / access_token
value TEXT 对应值
updated_at INTEGER 更新时间

表二：files

用于构建文件树与增量判断

字段 类型 作用
id TEXT PK OneDrive 唯一 ID
parent_id TEXT 父目录
name TEXT 文件名
is_folder BOOLEAN 是否文件夹
path TEXT 本地路径
ctag TEXT 内容版本标识
last_scan_ts INTEGER 上次扫描时间

两个关键字段说明

  • cTag：内容变更检测
  • last_scan_ts：用于标记-清除算法

四、核心模块设计

模块一：认证管理（Auth Manager）

对接 Microsoft Graph：

  • 令牌刷新接口
    POST
    https://login.microsoftonline.com/common/oauth2/v2.0/token

流程：

  1. 启动读取 refresh_token
  2. 请求前检查 access_token 是否过期
  3. 401 自动刷新
  4. 更新 SQLite

设计原则：

  • 全局共享 Token
  • 原子更新
  • 自动重试机制

模块二：同步引擎（Sync Engine）

这是系统最复杂部分。

全量扫描流程

  1. 记录 current_scan_ts
  2. 从 root 递归遍历
  3. 分页处理 nextLink
  4. 执行 Diff

Diff 逻辑

情况 A：新增

  • DB 无记录
  • 插入
  • 生成 .strm

情况 B：修改

  • cTag 不一致
  • 更新 DB
  • 重新生成 .strm

情况 C：未变

  • 仅更新时间戳
  • 不进行 IO 操作

→ 这一步极大提升性能

GC 清理机制

SQL 条件：

说明：

  • 本次扫描未更新
  • 说明已在云端删除

操作：

  • 删除本地 .strm
  • 删除 DB 记录

模块三：播放服务器

.strm 文件内容：

HTTP 服务流程：

  1. 接收 /play/:file_id
  2. 调用 Graph API 获取 downloadUrl
  3. 返回 302 重定向
  4. 错误返回 404

优点：

  • 直链永远最新
  • 不暴露真实 API 结构
  • Emby 端无感知
