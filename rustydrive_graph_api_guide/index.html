4. 获取 Refresh Token

4.1 授权代码流程（推荐）

  1. 构建授权 URL（个人账户或 E5 账户）
  2. 浏览器登录并授权应用访问
  3. 获取 authorization_code 并使用 client_id/client_secret 交换 token
  4. 记录 refresh_token，用于长期自动刷新

4.2 设备代码流程（CLI 场景）

  1. 请求设备码
  2. 用户在 https://microsoft.com/devicelogin 输入 code 并授权
  3. 使用设备码轮询 token
  4. 记录 refresh_token

5. Token 生命周期与自动刷新机制

  • Refresh Token：长期有效，90 天滑动窗口，定期使用可无限续期
  • Access Token：短期有效，程序自动刷新

6. 常见问题与解决方案

问题 原因 解决方案
Token 刷新失败 refresh_token 超期 重新获取新的 refresh_token 并更新数据库
权限不足 API 权限未授予 检查 Azure 应用权限，确保授予管理员同意
无法访问 E5 OneDrive 租户 ID 配置错误 确认租户 ID，添加 Sites.Read.All 权限
Client Secret 过期 Azure 客户端密钥过期 创建新密钥并更新 .env

7. 安全建议

  • 必须保护：client_secret、refresh_token、access_token

  • 避免：

    • 提交到 Git 仓库
    • 在日志打印完整 token
    • 与他人共享凭据

  • 最佳实践：

    • 使用 .env 文件，并加入 .gitignore
    • 限制 API 权限，仅授予必要权限
    • 定期轮换 client_secret
    • 监控 Azure 异常登录活动

10. Nginx 反向代理与 302 劫持配置

为了优化 Emby 播放和 RustyDrive Streamer 的直链获取，我们通过 Nginx 反向代理实现 302 响应透传，避免流量绕行服务器。以下配置适用于 Linux /etc/nginx/sites-available/emby_302：

配置说明

  1. proxy_redirect off：禁止 Nginx 修改上游 Location 响应头，确保 302 重定向直接透传给客户端。
  2. proxy_pass_header Location：保留原始 Location 响应头。
  3. proxy_buffering off：禁用缓冲，避免播放卡顿。
  4. Fallback 机制：当 RustyDrive 无映射时，回退到原生 Emby，保证稳定播放。
  5. 超时设置：快速获取直链，避免客户端长时间等待。
